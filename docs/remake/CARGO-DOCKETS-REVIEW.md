# Q18 荷札と荷物箱の実装確認（2026-09-30）

既存の幅広い木箱を四輪式の荷物錠で閉じる。丸い路線印は錠の輪の下にある。別の収納箱を室内へ増やさず、木箱の位置は既存の cargoBoxes に従う。蓋を開けている間はこの木箱を押せない。閉めてから通常の荷物移動を再開する。階段への道を空けたかどうかや、紙を見た履歴は解錠条件にしない。木箱の手前側は通常の撮影位置から届く。

六枚の荷物取扱票を、別紙の受領控・通過控の実例と比べる。受領控は枠内の丸、通過控は枠をまたぐ丸。対象の荷札は丸の受領扱い四枚（扉閉6・通過2・ベル8・停止4）、通過扱いの丸3、別路線の三角9。出来事順は既存の recordings.ts だけを参照し、二本の閉鎖音をそろえたずれ3から扉→通過→ベル→停止、6284を得る。UIへ正解順や印の解説は常設しない。

正しい輪を合わせて留めを回すと蓋が開く。交換灯具と荷物経路控を別々に取る。控には9月8日、丸線、給水槽―鉄塔、尾部照合印があり、後続Q26で同じ貨物を照合する。控は持ち物から読み直せる。灯具も既存の画像アイコンを使う。全景・箱の接写・持ち物は内容物の同じ所在を参照する。録音、荷札、任意の記録の閲覧は入手条件にしない。

代表素材五点は built-in image_gen で作成。幅広い木箱の閉／開の透過素材、閉／開の接写写真、錠の接写。写真はWebPへの符号化のみ、透過素材はalphaを保ってtrim・最大幅1400pxへ縮小。紙の印字と可動の数字は写真素材の上へ実行時に描く。採用一覧は docs/remake/assets.json、原指示は docs/remake/prompts/imagegen-calls.json。錠の接写は1180×610pxの範囲を最大1100px幅で表示し、写真の実画素を超えない。390px画面で輪の操作幅49.2px。

確認した範囲：90テスト、build、149点の作り直し素材の参照・alpha検査。PC1440×900／タッチ390×844で六枚と実例、荷札の個別拡大、誤入力時の留め、四輪の操作、6284での解錠、二品の取得と消失、再読込保存。北ホーム→地下横断通路→荷物室→幅広い木箱→錠の通常入口でも解錠、閲覧ノートなしで開くことを確認。箱の開閉は全景へ反映する。表示の層番号と共通写真CSSの競合を修正し、内容物を箱内へ戻した。

G1/G2/G3全体の合格を示すものではない。今回の箱写真と既存部屋の生成写真は、共通の木箱と照明を参照した代表状態。厳密なレンズ・箱の寸法・全状態の接触判定は未証明。Q26の貨物現場、Q16の灯りの観測、通常の灯具／覆いの入手はまだ別途接続する必要がある。箱は手前から操作できるため、Q17の解法を収納箱の履歴条件として追加しない。
