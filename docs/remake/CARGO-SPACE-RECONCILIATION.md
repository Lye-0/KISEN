# 荷物室の撮影位置と共通空間の修正

## 解消した不一致

前チェックポイントの CargoRoom は駅舎南壁より外の仮カメラを持っていた。今回は `geometry.ts` の cargo カメラ `(13.5,-11.8,1.55)` を、駅舎内 `x=12..15/y=-12..-6` の北向き視点へ固定し、`cargoGeometry.ts` と実画面が同じ値を使うようにした。

床の案内溝は横0.8m・縦0.55mの3列6行。荷の大きさと可動域を室内に収め、21の有効配置すべてで境界・高さ・戸前の空きを検査。操作数と衝突の組み合わせは変えず、長箱・幅箱・台車・棚の判断を維持した。東の階段戸は x=15/y=-9.4..-8.5、西の駅務室戸は x=12/y=-10.2..-8.8。初期棚の投影は階段戸を覆い、退避すると戸が見える。

`render-cargo-guide.mjs` の投影図から空の室内写真を生成。以前の写真を併せた候補は古い画角を引き継いだため不採用。投影図単独を基準にしたマスターで、遠い北壁・左右の戸・六本の溝の位置を照合し、左の通行戸を開いた採用写真、東の戸も開いた差分を制作した。写真の画角へ別の世界座標を後付けしていない。

## 南外壁との比較

箱の手前側から南壁を見る通常視点を追加。南窓は外壁の第5間にある三列二段の一窓で、両脇の柱と梁が一間を囲う。床操作の北向き写真に見える小さな北窓とは向きも形も区別する。室内既知5間と外壁6間の比較に荷物室の一間を加えられるが、独立した初見評価は未実施。

## 検証

- `cargoGeometry.test.ts`：カメラが室内、21配置が境界内、階段戸前の占有と通行判定が一致、初期棚が戸を覆う投影、退避後の露出。
- 保存の短い荷配置・干渉配置・範囲外を拒否。77テスト合格。
- PC1440×900とタッチ390×844で、初期状態・6操作後・開扉・南窓を目視。元写真1672×941に対して、荷物室はPC約1119px／タッチ640px幅で表示。部品の表示倍率も元画素以下。タッチは実際のtapで同じ操作を確認した。
- 素材監査：旧版70、新版122（音源2を含む）。採用台帳外ファイルなし。候補は生成元と研究側に残し、今回の本番素材は採用3枚のみ。

## 未合格の範囲

Q15/G1全体はまだ未合格。地下の既存写真は短い階段だけで荷物室と北ホームを結ぶように見え、計画の線路下z=-3・長い横断通路と照合し直す必要がある。地下窓から地上線を見下ろす現行写真も、観測点の高さを確定してから再審査する。荷物室のカメラ修正を駅全体の空間合格へ広げない。

次の核心はQ20の通過側の券実例とQ27の現物レバー。支えを使うQ16、地下通路の連続、Q25の線路本数・屋根下の連続、全編の章展開・帰還は継続。
