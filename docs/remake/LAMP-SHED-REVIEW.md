# 灯具小屋・掲示・釣り合い箱の代表検査

通常導線で灯具と停車灯の覆いを取得できるようにした。Q10の紙面とQ22の釣り合い箱を対象にした代表実装で、全ゲームのG1/G2/G3合格を意味しない。

## 現物と状態

- 駅前の既存掲示板から四枚の紙を手に取る。紙は表裏を保ち、左右の置き先を選択またはドラッグする。甲・乙・丙・丁の両辺の二穴は証拠台帳の値を共有する。
- 丙右と甲左のみが、表を上にした同じ印刷高さで二穴とも一致する。写真は小屋へ続く側道の一枚から左右を分けたもの。番号4706の四桁は接合辺で一字ずつ二分して印刷し、並べた紙で復元する。別の紙面は別の半字と写真の範囲を持つ。
- 小屋は駅舎東端の脇から進む。外観カメラは[22,-13,1.65]、目標[21.5,-5,1.6]、f=650。小屋の床はx=20..23、y=-5..-2、壁高2.8。南の戸を開けて入室する。採用した開扉写真は左蝶番で外側へ開く。戸を通った後も開いた状態を描く。
- 普通の灯具は西寄りの壁金具に一つ。既存の単体灯具を参照した設置写真を共通画素位置で重ね、取得後は同じ空の金具を残す。所有場所はlightRackからinventoryへ変わる。
- 保管箱は固定天板と、下蝶番で手前へ開く前面の蓋。腕の支点は固定天板側へ残るため、開放しても腕と錘は消えない。左右に三つずつ吊り位置があり、左の質量2・右の質量3と支点からの距離でモーメントを計算する。左3・右2でのみ釣り合う。片方を外した状態は解錠しない。
- 腕が傾いても鎖・錘は重力方向へ下がる。取り外した錘は足元へ置く。位置変更・ドラッグ・選択後の押し操作を同じ状態へ結び、開放中は吊り位置を固定する。蓋を閉めれば錘を再び外せる。
- 二枚の覆いは箱の底へ置き、接写と全景で同じ所在を使う。取得後は両方とも消え、持ち物には同じ二枚が残る。所有場所balanceChestからinventoryへの取得は開放した小屋の箱に限る。

## 表示と実操作

PC1440×900とタッチ390×844で、紙の組合せ、表裏、記録、誤入力、4706での入室、灯具の取得、錘の配置、蓋の開放、覆いの取得、再訪、保存再読込を確認した。PCでは左錘を実際に外側へドラッグして[1,1]から[2,1]になることも確認した。タッチの実ドラッグでは左錘を支点側へ動かして[3,2]から[2,2]へ変わり、写真の吊り位置を押して[3,2]へ戻せた。

通常の探索は荷物室→駅務室→待合室→駅前→東の側道→小屋の順に実操作した。記録欄が空でも戸と箱を現物の状態で開け、二品を取得できる。履歴や正解フラグを条件にしない。

写真の拡大領域が全面に残り、留めを押せなくなる不具合を実操作で発見した。小屋の箱では隅の44pxボタンだけが拡大を受けるように修正。元画像を超えない倍率へ制限し、PCは約1.454倍（表示1150px→1672px）、タッチは2.7倍（390px→1053px）。選んだ錘に合わせて拡大位置を移し、開放後は箱の底へ向ける。通常の閲覧写真では全面を押す拡大を維持し、乗車券控の既存写真で約402.5pxの全面領域・2.7倍の拡大と復帰を再確認した。

全94テスト、TypeScriptと本番ビルド、旧70点＋作り直し159点の素材監査が通った。実操作中のページエラーはなかった。写真・タッチの検査結果は `verification/2026-09-30-lamp-shed/shed-*.png` に保存する。

## 未確認・後続

外観・室内の大きさと操作物の読解・状態継続を代表検査した。写真の厳密なレンズ一致、窓の最終観測線と広域路線の対応、箱の留めと腕の機械的な連動詳細はG1へ残る。Q16の照射、Q23のベル、Q29の保持ピンの扱い、忘れ物・貨物の現場・帰りの車内と終幕は後続作業。現行既定の入口は旧版のまま。

UI点検スキルへの一般化はユーザーの明示許可後に共有スキルへ反映した。不可視の拡大・ドラッグ領域が別の操作を遮っていないか、強制クリックを使わず確認する手順を既存の代表確認へ統合し、構造検証が通った。
